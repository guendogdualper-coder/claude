## 3. App-Datenschutz (*App Privacy*, „Datenschutzangaben“)

Abgeleitet aus `docs/google-play/datensicherheit.md` (was der Code wirklich überträgt) und passend zu
`ios/App/App/PrivacyInfo.xcprivacy`. Apple fragt anders als Google. Es gibt kein „optional“, und Apple fragt, ob die Daten
**mit der Person verknüpft** sind und ob sie zum **Tracking** dienen.

**Erste Frage:** „Erheben Sie oder Ihre Drittanbieter Daten aus dieser App?“ → **Ja, wir erheben Daten aus dieser App.**

**Datentypen ankreuzen:**

| Kategorie (DE / EN) | Datentyp | Ankreuzen? | Was genau |
|---|---|---|---|
| Kennungen / *Identifiers* | **Nutzer-ID** / *User ID* | **Ja** | Firebase-Konto-ID (uid), Kontoname, Charaktername. Apple zählt Spielernamen und Konten-IDs hierzu (nicht zu „Name“). |
| Kennungen / *Identifiers* | **Geräte-ID** / *Device ID* | **Ja** | zufällige Gerätekennung `seelenstein.geraet`, mit Konto in der Cloud gespeichert. Keine Werbe-ID (IDFA). |
| Nutzerinhalte / *User Content* | **E-Mails oder Textnachrichten** / *Emails or Text Messages* | **Ja** | Briefe der Spielerpost (Betreff, Text, Absender, Empfänger) und Chat-Auszüge in Meldungen |
| Nutzerinhalte / *User Content* | **Gameplay-Inhalte** / *Gameplay Content* | **Ja** | Spielstand, Charaktere, Ausrüstung, Fortschritt im Konto |
| Nutzerinhalte / *User Content* | **Andere Nutzerinhalte** / *Other User Content* | **Ja** | Angebote im Auktionshaus, Text in Meldungen, Aussehen der Figur |
| Kontaktinformationen | Name, E-Mail, Telefon, Adresse | **Nein** | Es gibt keine echte E-Mail. Die interne Adresse `name@spieler.seelenstein.app` wird aus dem Kontonamen gebildet. |
| Standort, Gesundheit, Finanzen, Kontakte, Browserverlauf, Suchverlauf, Käufe, Sensible Infos | – | **Nein** | |
| Nutzungsdaten / *Usage Data* | Produktinteraktion, Werbedaten | **Nein** | keine Analyse, keine Werbung |
| Diagnose / *Diagnostics* | Absturzdaten, Leistungsdaten | **Nein** | kein Absturz- oder Analysedienst |
| Fotos, Videos, Audio, Kundensupport, Sonstige Daten | – | **Nein** | |

**Für jeden angekreuzten Typ** fragt Apple dasselbe:

| Frage | Antwort für alle 5 Typen |
|---|---|
| Wofür werden die Daten verwendet? | **App-Funktionalität** (*App Functionality*). Bei Nutzer-ID, Textnachrichten und anderen Nutzerinhalten **zusätzlich** nichts weiter. Meldungen dienen dem Schutz der Spieler und gehören zur App-Funktionalität. Kein Tracking, keine Analyse, keine Werbung, keine Produktpersonalisierung. |
| Sind die Daten mit der Identität verknüpft? (*Linked to the user*) | **Ja**. Sie hängen am Konto. |
| Werden die Daten für Tracking verwendet? (*Used for tracking*) | **Nein** |

**Ergebnis im Store („Datenschutzetikett“):** „Mit dir verknüpfte Daten: Nutzerinhalte, Kennungen“, „Daten, die zum Tracking
verwendet werden: keine“.

Hinweise:

- **Wer ohne Konto spielt**, gibt nichts davon ab. Apple will trotzdem alles angegeben haben, was die App erheben *kann*.
- Der Mehrspieler-Chat läuft direkt von Gerät zu Gerät und wird nicht gespeichert. Apple zählt nur Daten, die „erhoben“ (also
  vom Entwickler oder seinen Diensten gespeichert) werden. Der Chat taucht deshalb nur über die Meldungen auf.
- Firebase (Google) speichert **im Auftrag**. Apple wertet das nicht als Weitergabe an Dritte, solange Google die Daten nicht
  selbst nutzt. Keine Tracking-Abfrage (ATT) nötig.
- Die lokale Erinnerung an die Tagesbelohnung wird nur auf dem Gerät geplant. Es entstehen keine Daten.
- **Konto löschen:** Apple prüft, dass man das Konto **in der App** löschen kann (Einstellungen → Konto → Konto löschen). Das
  gibt es. Zusätzlich ist `https://seelenstein.online/konto-loeschen.html` vorhanden.

## 6. Wenn Apple ablehnt – Antwortvorlagen (Englisch, im Resolution Center)

### 6.1 Richtlinie 4.2 – Minimum Functionality („App ist nur eine Website“)

Das ist die wahrscheinlichste Ablehnung. Antwort anpassen und abschicken (ggf. mit Bildschirmvideo):

```text
Hello App Review team,

thank you for reviewing Seelenstein. We would like to clarify how the app goes beyond a repackaged website:

1. Seelenstein is a full real-time 3D game (WebGL), not a website: 5 character classes with 60 skills, 9 maps,
   100+ monster types, dungeons, raids, a crafting/blacksmith system and real-time online multiplayer with groups,
   guilds, trading and duels. Gameplay is rendered locally on the device; the content is not a collection of web pages.
2. The iOS app adds native functionality that the website does not have:
   - haptic feedback via the Taptic Engine for hits, level-ups and crafting,
   - opt-in local notifications for the daily login reward,
   - the native share sheet to invite friends,
   - in-app Safari views for external links,
   - native offline handling with automatic reconnect, background audio pause and game-state saving,
   - full-screen landscape presentation with hidden system UI and screen kept awake during play.
3. The app contains no browser-like UI and does not allow navigation to arbitrary websites.

We have attached a short screen recording showing these features. If there is a specific feature you would like to see added
for approval, please let us know and we will gladly implement it.

Best regards,
[NAME]
```

Hilft das nicht, gibt es zwei Wege: (a) einen Anruf anfragen (*Request a call*), (b) weitere native Funktionen einbauen lassen,
z. B. **Game Center** (Bestenlisten für Stufe/Arena-Wellen, Erfolge). Das bringt bei Spielen erfahrungsgemäß am meisten. Dazu
Bescheid geben, das ist eine Änderung an `ios/` und `js/nativ.js`.

### 6.3 Richtlinie 1.2 – User-Generated Content

Antwort: die Punkte aus den Prüfer-Notizen (Regeln vor dem ersten Chat, Melden, Blockieren, Reaktion binnen 24 h)
nennen und den Weg im Spiel beschreiben.

Verlangt Apple ihn, Bescheid geben: Er lässt sich in `js/spielerschutz.js` nachrüsten.

cloud data immediately.“ Bildschirmfoto anhängen.
